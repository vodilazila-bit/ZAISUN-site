# ZaiSun — контекст проєкту

Інтернет-магазин дитячого одягу. Власники: **Володя** (технічна частина, реклама,
аналітика) і **Мирослава** (товари, фото, Instagram, адмінка). Луцьк.
Мова спілкування — українська.

---

## Як працювати

**Робити, а не перепитувати.** Якщо задача зрозуміла — виконувати. Якщо в ній
суперечність — вирішити самому й ОКРЕМО написати, що саме вирішив і чому.

**Перевіряти реально.** Не «код виглядає правильним», а прогін по всьому каталогу
й перевірка на живому сайті. Синтаксична перевірка нічого не доводить: код без
половини функцій теж синтаксично коректний.

**Коротко, по суті.** Без передмов і переказу того, що щойно сказав користувач.

## Архітектура

`zaisun.com.ua` — SPA на GitHub Pages, гілка `main`.

| Файл | Що це |
|---|---|
| `index.html` | увесь сайт: каталог, картка, кошик, оформлення, пошук, аналітика |
| `data.js` | каталог: `const DATA = {tree, filters, products, colorhex}` |
| `admin.html` | адмінка Мирослави |
| `tools/gen_pages.js`, `tools/gen_feed.js` | генератори сторінок і фіду |
| `t/` | статичні сторінки товарів (генеруються) |

**Меню каталогу — хардкод `MENU_DEF` в `index.html`**, не з дерева категорій.
Створити категорію в `data.js` недостатньо — треба додати пункт у меню.
Ключі стійкі (`?cat=kbodi`), є `LEGACY_MENU` зі старими посиланнями для реклами.

**Приймач замовлень** — Apps Script «ZaiSun Relay», код поза репозиторієм.
Доступу з чату немає, передається файлом. Оновлення: Ctrl+A → вставити → Ctrl+S →
**Ввести в дію → Керування розгортаннями → ✏️ → Нова версія**.
«Нове розгортання» НЕ тиснути — змінить URL, і сайт перестане бачити релей.

## Обов'язковий порядок роботи з репо

Мирослава редагує `data.js` через адмінку **паралельно** — конфлікти нормальні.

```bash
for i in 1 2 3 4 5; do
  git fetch -q origin && git reset --hard -q origin/main && git clean -fdq
  python3 my_change.py || { echo FAIL; break; }
  V=$(grep -o 'data\.js?v=[0-9]*' index.html|head -1|grep -o '[0-9]*')
  sed -i "s/data\.js?v=$V/data.js?v=$((V+1))/g" index.html
  git add -A && git commit -q -m "опис, data.js v$((V+1))"
  if git push -q origin HEAD 2>/dev/null; then echo "PUSHED"; break; fi
  sleep 5
done
```

Зміну оформлювати **скриптом**, бо при ретраї її доведеться застосувати наново
до свіжого стану. `git clean -fd` видаляє невідстежені файли — генератори
тримати поза репо.

**Версію `data.js?v=` піднімати завжди**, інакше браузери покажуть кеш.
При відкаті теж **піднімати вгору**, а не повертати назад.

**Чекати деплой** через GitHub API до статусу `built` — від 30 секунд до 3 хвилин.
`raw.githubusercontent.com` кешує окремо й відстає ще довше.

## Структура товару

```json
{
  "id": 860, "name": "...", "price": 335, "old": 0,
  "stock": true, "nw": true, "hidden": false,
  "sizes": ["56","62"], "var": {"56":{"p":335,"o":0,"s":true}},
  "color": "Білий", "hex": "#FFFFFF",
  "cats": ["<uuid>"], "catn": ["Боді"],
  "photo": "file.jpg",
  "opts": {"Вид": ["квітка","бублик"]},
  "optup": {"Вид": {"квітка": 5}}
}
```

- `cats`/`catn` — паралельні масиви однакової довжини
- товар у підкатегорії має бути і в батьківській
- `stock:false` — зникає зі списків, доступний за посиланням і у фіді
- `hidden:true` — зникає звідусіль, включно з фідом
- `season` рахується на льоту, у `data.js` не зберігати
- **при зміні ціни міняти і `price`, і `var[розмір].p`** — інакше картка покаже
  стару ціну при виборі розміру

### Перевірки після зміни `data.js`

Унікальні id, `len(cats)==len(catn)`, немає битих категорій і товарів без
категорій, немає дублів назв серед видимих, усі фото на диску, лічильники `n`
збігаються, `optup` не посилається на неіснуючі варіанти.

## Граблі

**Не робити висновків із внутрішніх чисел.** Одного разу було заявлено, що в
«Шапках» лише 2 товари — це було значення `n` у дереві. На сайті їх 218.
Спершу дивитись, як це виглядає для покупця.

**Шукати причину, а не симптом.** Проблема з `purchase` спливала тричі з різних
боків, і щоразу лагодився симптом. Справжня причина знайшлась на третій раз.

**Тільки точкова заміна відомого фрагмента.** Вирізання «від маркера до маркера»
одного разу знищило дві функції разом із зайвим. Синтаксис лишився чистим,
сайт зламався.

**Перевіряти, чи немає другого такого місця.** Вікно подяки після оплати існує
у двох варіантах — виправили одне, друге лишилось старим.

**Тестові функції не повинні чіпати бойові дані.** `testGa4Purchase` надсилала
справжню подію на справжнє замовлення і двічі створила зайві покупки в GA4.

## Аналітика

**GA4** (`G-R0C1CM969C`): `view_item`, `add_to_cart`, `begin_checkout`,
`purchase`, `paid`.
`purchase` для mono шле **сервер** (релей) при підтвердженні оплати — браузер
його для mono не шле, бо клієнт часто не повертається на сайт.

**Google Ads** — PMax, Merchant Center, `gclid` зберігається в куку на 90 днів
і пишеться в таблицю замовлень.

**Meta** — піксель + серверний CAPI з накладних НП, дедуплікація за `event_id`.
